# OctoAcme Role Onboarding Checklist

## Purpose
This checklist helps new team members quickly understand their role, responsibilities, and key interactions within OctoAcme project management processes.

---

## General Onboarding (All Roles)

- [ ] Read [OctoAcme Project Management Overview](octoacme-project-management-overview.md)
- [ ] Review [OctoAcme Roles and Personas](octoacme-roles-and-personas.md)
- [ ] Study the [RACI Matrix](octoacme-raci-matrix.md) for your role
- [ ] Understand OctoAcme's core principles: Customer-first, Iterative delivery, Clear ownership, Data-informed decisions, Psychological safety
- [ ] Set up access to project management tools and repositories
- [ ] Identify your direct stakeholders and communication channels
- [ ] Schedule intro meetings with key collaborators

---

## Role-Specific Onboarding

### For Developers
- [ ] Review coding standards and style guides
- [ ] Set up development environment
- [ ] Understand branching strategy and PR process
- [ ] Review definition of done and acceptance criteria templates
- [ ] Join daily standup and sprint planning meetings
- [ ] Meet with QA Lead to understand testing expectations
- [ ] Review recent technical design documents

### For Product Managers
- [ ] Review current product roadmap and vision
- [ ] Understand prioritization framework and success metrics
- [ ] Meet with Business Analyst to understand requirements process
- [ ] Review customer feedback channels and analytics tools
- [ ] Meet with Executive Sponsor for strategic alignment
- [ ] Understand release planning cycle
- [ ] Review backlog grooming process

### For Project Managers
- [ ] Review [Project Initiation](octoacme-project-initiation.md) process
- [ ] Review [Project Planning](octoacme-project-planning.md) templates
- [ ] Review [Execution and Tracking](octoacme-execution-and-tracking.md) practices
- [ ] Understand risk management and escalation procedures
- [ ] Set up project tracking tools and dashboards
- [ ] Review communication cadence and stakeholder reporting
- [ ] Meet with Change Manager to understand change control process
- [ ] Review [Retrospective process](octoacme-retrospective-and-continuous-improvement.md)

### For Business Analysts
- [ ] Review requirements gathering templates and best practices
- [ ] Understand user story and acceptance criteria format
- [ ] Meet with Product Manager to align on current priorities
- [ ] Identify key stakeholders for requirements workshops
- [ ] Review business process documentation tools
- [ ] Understand validation and sign-off procedures
- [ ] Set up access to stakeholder communication channels

### For QA Leads
- [ ] Review testing strategy and quality standards
- [ ] Understand test planning and execution tools
- [ ] Review test automation framework and practices
- [ ] Meet with Developers to align on code quality expectations
- [ ] Review defect tracking and reporting procedures
- [ ] Understand release sign-off process
- [ ] Review quality metrics and SLAs
- [ ] Join sprint planning to understand testing scope

### For Change Managers
- [ ] Review change management process and policies
- [ ] Understand change request submission and approval workflows
- [ ] Set up access to change control board meetings
- [ ] Review change impact assessment templates
- [ ] Understand emergency change procedures
- [ ] Review change metrics and reporting requirements
- [ ] Meet with QA Lead to align on testing requirements for changes
- [ ] Identify key stakeholders for change communications

### For Executive Sponsors
- [ ] Review current project portfolio and strategic priorities
- [ ] Understand escalation procedures and decision frameworks
- [ ] Identify organizational blockers and resource constraints
- [ ] Set up regular touchpoints with Project and Product Managers
- [ ] Review executive reporting format and cadence
- [ ] Understand major milestone approval process
- [ ] Identify peer executives for stakeholder alignment

---

## First 30 Days - Key Milestones

### Week 1: Learn
- Complete general onboarding checklist
- Complete role-specific onboarding items
- Shadow team members in similar roles
- Attend all relevant recurring meetings as observer

### Week 2: Engage
- Begin participating actively in meetings
- Take on small, well-defined tasks
- Ask questions and seek clarification
- Build relationships with key collaborators

### Week 3: Contribute
- Own specific deliverables or activities
- Provide input on team discussions
- Start using project tools independently
- Give feedback on onboarding experience

### Week 4: Reflect
- Review progress with manager
- Identify any knowledge gaps or blockers
- Adjust role responsibilities if needed
- Document improvements to onboarding process
